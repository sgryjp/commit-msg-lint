# コミットメッセージの前処理とリント

## 状態と背景

**状態: 実装済み・検証中。** 現行 CLI の使い方は [CLI リファレンス](../references/cli.md)を参照する。 <!-- rumdl-disable-line MD089 -->
Windows 固有の動作と Git for Windows での実フック試験は未検証である。
本設計は、以前の明示フックモードと CLI オプションによる個別制御の案を置き換える。
判断理由は [ADR-0002](../adr/0002-default-message-filtering.md) に記録する。

主な調査資料は [Git 固有のコミットメッセージ入力調
査](../research/2026-11-13-git-commit-message-input.md)
である。Git の `commit-msg` フックは cleanup 前のメッセージファイルを受け取る。
フックの引数だけでは、実効 `--cleanup` や verbose 指定を確定できない。

## 目的と境界

- 通常の対話的コミットと verbose コミットで、編集用コメントや差分による誤拒否を減らす。
- Git の最終メッセージの完全再現はしない。実際には残る本文を検査から外す可能性も明示する。
- コミットごとの方針は環境変数で指定し、共有設定を書き換えない。
- 入力ファイルは変更せず、検査対象の行だけを選ぶ。
- [README の設計方針](../../README.md#design-philosophy)に従い、表示幅で測定する。 <!-- rumdl-disable-line MD089 -->
  警告とエラーの区別、および `--strict` の意味は変更しない。

## CLI の既定値と適用範囲

CLI は標準入力・`--edit <path>` とも、コメント除外と scissors 切断を既定で有効にする。
専用のフック用モードは追加しない。フックからは従来と同じ形で呼び出せる。

```sh
commit-msg-lint --edit "$1"
```

`--edit` のパス名や `GIT_EDITOR` からモードを推測しない。
公開ライブラリの `lint(input, config)` と Web デモは、従来どおり入力をそのまま検査する。
ライブラリや Web がプロセス環境変数を読み、暗黙に除外処理を適用することはない。
将来履歴検査を実装する場合も、完成済みメッセージには除外を適用しない経路を使用できる。

## 環境変数

| 変数 | 操作 | 未指定時 |
|---|---|---|
| `COMMIT_MSG_LINT_STRIP_COMMENTS` | コメント行を検査対象から除外する | 有効 |
| `COMMIT_MSG_LINT_CUT_SCISSORS` | scissors 行と後続を検査対象から除外する | 有効 |

両変数で同じ真偽値規則を使う。

- 真: `1`、`true`、`yes`、`on`。
- 偽: `0`、`false`、`no`、`off`。
- 英字の大文字・小文字は区別しない。
- 空文字、前後に空白のある値、その他の値、非 Unicode 値は終了コード `2` の設定エラーとする。
- 一方だけ指定した場合、他方は有効のままである。

同じ指定を設定ファイルや新規 CLI オプションには追加しない。
呼び出し側は、Git の実際の処理と指定を揃える責任を持つ。
例えば、完成済みメッセージを原文のままコミットする場合は次のように指定できる。

```sh
COMMIT_MSG_LINT_STRIP_COMMENTS=false \
COMMIT_MSG_LINT_CUT_SCISSORS=false \
git -c commit.verbose=false commit --cleanup=verbatim -F message.txt
```

これは POSIX シェルの例である。環境変数は linter の動作だけを指定し、Git の動作自体は変更しない。

## 前処理の順序と条件

1. 切断が有効なら、最初の scissors 行と後続を除外する。
2. コメント除外が有効なら、残った行のうちコメント接頭辞で始まる行を除外する。
3. 残りを現行の正規化・解析・リントへ渡す。

二つの処理は独立している。scissors の形をしたコメント行も、切断が無効でコメント除外が有効なら、
その行だけを除外する。順序を逆にして切断位置を失わないようにする。

### コメント行

接頭辞による行頭からの前方一致とし、複数文字の接頭辞にも対応する。
接頭辞が `#` なら `#note` もコメントだが、` #note` はコメントではない。

### scissors 行

正規化前の行が次の形に完全一致し、LF で終わる場合だけ認識する。

```text
<接頭辞> ------------------------ >8 ------------------------
```

先頭の空白、末尾の追加文字、CRLF、終端 LF のない最終行は一致しない。
この認識条件は固定仕様であり、Git の全バージョンへの自動追従は保証しない。

macOS の `Git 2.54.0 (Apple Git-157)` では、エディターが保存したメッセージに対する
`git commit -e --cleanup=scissors` で、LF のマーカーは切断され、CRLF のマーカーは切断されなかった。
CRLF の場合はマーカーと後続が残り、その後の整理で改行は LF になった。
Git for Windows での実測は行っていない。C ランタイムのテキストモード変換の有無だけで、
Git の読み込み結果は断定しない。今回は LF のみを維持し、実際の問題が確認された際に見直す。

## 接頭辞と Git の責務

少なくとも一方の除外処理が有効な場合、CLI が接頭辞を解決して純粋な前処理へ渡す。
前処理・パーサー・リント内部では Git を起動しない。

- フックから継承した環境と作業ディレクトリで Git を実行する。
- リポジトリ判定は Git に任せる。`.git` の存在や入力パスから推測しない。
- リポジトリ内では、`git config --null --get-regexp '^core\.comment(char|string)$'` 相当で
  両別名を設定順に取得し、最後の値を使う。include 等は Git に解決させる。
- 出力は NUL 区切りで解析し、値を勝手に trim しない。
- 正常な未設定の場合、およびリポジトリ外では、組み込み既定値 `#` を使う。
- 空値、改行を含む値、不正な出力、必要な Git の起動・設定取得失敗は終了コード `2` とする。
- `auto` は大文字・小文字を区別せず拒否する。Git が選んだ接頭辞を推測しない。
- 失敗時は、Git 側の固定接頭辞への変更か、両処理の無効化を案内する。
- 両処理が無効なら、前処理用の Git 呼び出しは不要である。
  設定ファイルの自動探索は別であり、`--config` がなければ Git を呼びうる。
- Windows の非対話的な Git 子プロセスはコンソールを表示しない。

接頭辞の環境変数・CLI 上書きは今回実装しない。Git 非依存の前処理や安定したエージェント実行のための
価値は認め、[TODO](../../TODO.md) に将来検討事項として残す。

Git 2.45 未満では複数文字や別名の扱いが異なるため、完全互換を約束しない。
`git -c` のフック内での可視性は実装時の実フック試験で確認する。

## 行構造と診断

元入力の 1 始まりの行番号を持つ論理行列を作り、構造判定とリントに渡す。
除外行は列に含めないが、残った行の診断は元入力の行番号を使う。
診断形式、ルール ID、ソート順、終了コード `0` / `1` / `2` は維持する。

- 残った最初の行を Header とする。先頭空行を飛ばさない。
- Header、空行、コメント、Body の並びは、除外後に空行一つの区切りとなる。
- Header、コメント、Body の並びは、区切り不足を Body の元行番号で報告する。
- 全行除外時は空 Header として扱う。`header-format` が有効なら元入力の 1 行目に報告し、
  除外後に空になったことを説明する。ルールが無効なら報告しない。
- CRLF の通常行の正規化、末尾 LF を最大一つ除く扱い、単独 CR の制御文字診断は維持する。
  scissors の判定だけは正規化前の終端を使う。

Git の空白整理は追加しない。行末空白、先頭・末尾の空行、連続空行は既存ルールに渡す。
Git が後で整理する空白を本ツールが違反として報告する可能性は残る。

## 意図的な不一致と対象外

- エディター使用・非 verbose の通常の `strip` では、Git は scissors 形のコメント行だけを削除し、
  後続を残す。本ツールの既定値は後続も除外する。
- `-m` / `-F` の既定ではコメントが残るが、本ツールの既定値は除外する。
- コメントや scissors を本文として扱う場合は、環境変数で該当処理を無効にする。
- Footer のヒューリスティック、Trailer のルール、特殊 Header の免除は変更しない。
- UTF-8 入力の制限を維持し、エンコーディング変換は追加しない。
- 履歴・範囲検査、フックの設置・管理、フックが実行されない経路の保証は今回の対象外である。

## 検証方針

1. 純粋な前処理とリントで、全四通りの処理選択、厳密な行認識、元行番号、全行除外を確認する。
2. CLI で環境変数、設定取得、不正値、標準入力、`--edit`、終了コードを確認する。
   テストは新しい環境変数を明示的に設定・除去し、実行者の環境を継承して結果を変えない。
3. 一時リポジトリの実フックで、エディター、`-v`、`-m`、`-F`、cleanup、接頭辞、include、
   worktree、`git -c` を代表例で試験する。Git の最終結果との意図的な差も確認する。
4. 公開 `lint`、Web、表示幅、重大度、`--strict`、Footer、UTF-8 の既存動作を回帰確認する。
5. 既存 CI の Linux / Windows と WASM ビルド、手元の macOS で検証する。
   試験した Git のバージョンを記録し、未実施環境や古い Git の対応を実施済みとして扱わない。
