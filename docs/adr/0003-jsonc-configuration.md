# 設定ファイルに JSONC を採用する

**状態: 実装済み。**

設定ファイルの形式には、コメントと末尾カンマを許可する JSONC を採用する。

TOML は人間による記述は行いやすいものの、スキーマ定義に従ったテキストエディタでの
自動補完や検証には追加の仕組みが必要である。
その点で JSONC は JSON Schema による自動補完や検証がエコシステムでサポートされて
おり、かつ人間による記述の行いやすさも優れている。これが選択の理由である。
ただし JSONC の構文や末尾カンマの扱いはツールによって異なるため、
CLI と Web デモでは同じ設定解析を使い、受け付ける構文と検証結果を揃える。

## 構造化された設定診断

設定の構文・検証エラーを構造化する際も、CLI と WebAssembly は `Config::parse` を共有する。
`jsonc-parser` の AST を使うことで、重複キーを保持し、JSONC 入力内の UTF-8 バイト範囲を
診断に付けられる。Serde 型への直接解析ではこの情報を保持しにくいため、設定項目を AST から
明示的に読み取る。その分フィールド定義の対応付けが必要になるが、複数件の収集と LSP 向け
位置変換は設定診断の基本契約から分離する。
